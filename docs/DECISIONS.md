## 技术方案依据

首选客户端方案为建议而非既定栈：共享两端业务代码，适配本机已有 JavaScript 工具链；仍必须分别验证两端原生行为。

- [Expo Router](https://docs.expo.dev/router/introduction/)：原生导航。
- [ImagePicker](https://docs.expo.dev/versions/latest/sdk/imagepicker/)：系统相册和拍照；拍照需真机验证。
- [Location](https://docs.expo.dev/versions/latest/sdk/location/)：设备定位；餐馆检索是独立数据能力。
- [SQLite](https://docs.expo.dev/versions/latest/sdk/sqlite/)：跨重启保存本地数据。
- [Development builds](https://docs.expo.dev/develop/development-builds/introduction/)：需尽早验证自有原生构建，Expo Go 与 Web 不替代安装包验收。

Flutter 也是双端候选，但本机未发现其工具链。双端原生 Swift/Kotlin 会分别维护平台界面；若用户选择单端且 PRD 出现平台专属需求，再评估取舍。尚未锁定框架或依赖版本。
