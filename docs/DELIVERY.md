# 首版范围、阶段与验收

基线：`PRD.md` V0.1（2026-10-07）及用户的开发要求。本文是实现追踪表，不替代原始 PRD。所有产品功能当前均未实现；“首版内分阶段”不等于将能力移出首版。

S1 闭环：打开 APP → 设置条件 → 获取餐馆推荐 → 选择（计划）→ 确认吃过并保存 → 重启查看 → 下一次推荐参考确认历史。导航与“帮我选”不能自动确认吃过。

S3 不以 S2 的 AI 服务成功为前提；AI 供应商或预算未就绪时，继续手动路径和共享投票，不等待识别服务。

各阶段都维护启动方式、实际验证结果、未完成/模拟项和本地 commit。原生构建或真机受环境限制时保留待验收状态，不以浏览器代替。

## 后续迭代与明确不做

- 首版之外：更大范围新店发现、长期/月度回顾、多餐自动整理导入、固定饭搭子、长期群体偏好、更广菜式与份量辅助、具备数据支持后的维矿定量。
- 商家认领、菜单维护和合作导流在核心使用验证后另立需求。赞助须标识且不能覆盖硬限制。
- 交易、支付、配送、公开社区、复杂好友/运营后台、优惠券、积分商城和签到惩罚不在本次首版。
- 人工维护真实店铺已经是合法首版来源；地图接入的时间由供应商授权与覆盖决定，不能拿示例数据验收真实推荐。

## 测试及真实性边界

- 推荐规则单元测试：稳定输入与可解释排序，测试行为边界，不仅复述实现。
- 数据库/任务集成：记录状态和版本、幂等、删除、回调乱序；真实本地持久化需关闭重开 APP 验证。
- 共享后端：多客户端并发投票、轮次、截止、重复与角色权限；单机演示不能算多人通过。
- 原生 E2E：完整选餐—确认—保存—重启—再推荐路径；另测权限拒绝、弱网和外部服务失败。
- AI：授权的单人、混合、合餐、非食物样本，评价拒绝不确定输入及用户纠正成本；营养真值须有独立食物/配方/份量依据。
- 性能目标尚未验证：自有餐馆推荐 P95≤2 秒、手动保存 P95≤1 秒、AI 15 秒后后台化、单人餐操作中位数≤30 秒（AI 等待单列）。报告设备、网络和数据量。
- 20–30 人、两周试点及采纳/留存阈值均是建议，不承诺工期或统计显著性。服务费用在获得实际基线后评估。
